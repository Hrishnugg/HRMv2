## 8. Extracted specifications (verified from code, 2026-07-24) — feeds §3.2

**Two corrections to statements made in the meeting (get these right when talking to the professor):**
1. **Continuous worlds are NOT 64×64 m.** They are unit squares: `side_len = 1.0` world units for most families, `2.0` for large families (`build_anchor_specs`, `continuous_prm_common.py:292`). The "64×64" is the **field raster resolution** (64×64 pixels for the U-Net input), and the discrete program's grids (20×20–256×256 cells) are a separate substrate. Physical units in the continuous program are abstract; scale is defined relative to obstacle radii (0.022–0.115 × side) and agent speed.
2. **PRM node count is FIXED, not map-scaled, in every canonical run.** All C7→C14 runs construct `RoadmapConfig(n_nodes=192, k_neighbors=7)` — exactly 192 sampled nodes, k=7. (The library default is 256/14, used by early C3-era stages; a "big" cloud variant used 384/18. Per-stage values should be tabulated, but "scales with map size up to 192" is not what the code does.)

**Static families (generator = ours; cite artifact/code; all lengths in fractions of side_len):**
- Base anchors (unit square, circle mode unless noted): open 3–8 circles r 0.025–0.060; clutter 18–30 r 0.025–0.070; narrow: two barrier walls with gap width 0.17 + 4–10 clutter circles; large-clutter (side 2.0) 35–55 r 0.045–0.115; OOD: extra-dense 42–68; tiny-passage gap 0.10 + 8–16 clutter; large-open/large-narrow (side 2.0); rectangles 14–24 axis-aligned rects.
- C7 hard families (axis-aligned thin-wall constructions): **spiral** = 4 serpentine vertical walls, alternating gap side per wall, spanning x∈[0.22, 0.78]·side; **bugtrap** = classic U-pocket: solid vertical back wall + two horizontal arms + a mouth lip that closes the center of the opening (3 walls + lip); **rooms / rooms-large** = 2×2 rooms from one vertical + one horizontal partition wall, one doorway each, doorways biased toward edges; **maze / maze-dense** = wall mazes with per-spec gap widths (dense gap 0.115 — the corridor constriction that makes it the hard held-out family).
- Train/held-out split (canonical C7): train families maze, rooms, spiral(?) — [verify exact three from C7 config: `targets` vs `train_tasks`] — held out: maze-dense, bugtrap, rooms-large.

**Dynamic suites (C8; deterministic patrollers, exact law):** obstacles are `MovingCircle` patrollers sweeping a **linear span back-and-forth (triangle-wave position)**; per suite: 3–5 patrollers, radius 0.055–0.080 × side, span 0.36–0.50 × side, period 0.14–0.30 × (t_max·dt) (each patroller crosses its span **twice per period**), lateral jitter of the sweep center ≤ 0.02–0.10 × side; agent speed v = 0.060 units/s (0.120 on the side-2.0 large-rooms suite); dt = 1.0 s; t_max = 110–140 steps (dense 140, large-rooms 130, others 110). Per-suite table: maze/rooms/spiral 3 patrollers r 0.075 span 0.38–0.40 period 0.14; dense 4 patrollers r 0.062 span 0.42 period 0.17 t_max 140; crossing (control) 4 r 0.055 span 0.50 period 0.30 lateral 0.10; large-rooms 5 r 0.075 span 0.36 period 0.14 v 0.120.
- "53 usable maps": a training world is usable iff the world builds, the PRM connects start (node 0) to goal (node 1), and the space-time problem is solvable from (start, t=0) under the moving patrollers (finite backward-Dijkstra value) — the collect pass draws seeds until enough pass.

**Scalar features (C5-hard profile used from the hard maps onward):** per-node token sequence, seq_len = 1 + nearest-obstacles + rays + 1; hard profile: 12 nearest obstacles, 48 rays × 96 steps, 16 sector tokens; token_dim 16. Base profile (easy anchors): 6/16×80.
**Field input:** 8-channel 64×64 raster (occupancy, reachable-free, clearance, start/goal encodings, x, y, normalized Euclid) + W temporal channels for aware dynamic models (W=8) — blind twins W=0.
**Optimization defaults:** batch 256, base epochs 10 (expert 8), lr 2e-4 (expert 1.5e-4), weight decay 1e-4, grad clip 1.0, residual cap 4.0, AdamW.
