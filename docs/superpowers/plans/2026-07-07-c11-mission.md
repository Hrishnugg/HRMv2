**Grid.** Configs: A=(`"C_hard_maze"`, config_idx 0, no doors), B=(`"C_hard_rooms_large"`, 1, no doors), C=(`"C_hard_maze"`, 2, doors via `C11P.door_adj_valid_factory`). K ∈ {0, 2, 4, 8}; config C is DROPPED at K=0 (degenerates to A) → 11 cells. `K_MAX = 8`.

**Worlds.** Build: `H7.install_c7_hard_maps()` once; `spec = C.build_anchor_specs()[spec_name]`; `world = C.build_world(spec, seed, 0.45)`; `rm = C.build_prm(world, C.RoadmapConfig(n_nodes=192, k_neighbors=7), seed + 17)`; skip on None/`RuntimeError` from `C11P.sample_mission(rm, world, K, seed)` / door placement / `not C11P.mission_reachable(oracle)` — exactly the probe's `eval_cell` skip semantics (read it first). K=0: mission = empty tuple `()`; `product_oracle(rm, ())` is the (1, N) plain-goal field; doors never placed.
- TEST seeds: `1234 + 7919*w + 104729*config_idx + 15485863*K`, 25 valid worlds/cell (K∈{2,4,8} = the probe's exact worlds).
- TRAIN seeds: `900001 + 7919*w + 104729*config_idx + 15485863*K`, 40 valid worlds/cell.

**Labels & residual target.** Per world: `oracle = C11P.product_oracle(rm, wp, adj_valid)` (shape (K+1, N)); `hl = C11P.h_legsum(rm, wp)` (CALLABLE `hl(i, s)`). Train rows = all (i, s) with `oracle[s, i] < C.INF / 10.0`; target `y = clip((oracle[s,i] - hl(i,s)) / world.side_len, 0.0, 4.0)` (B = 4.0 = `C.TrainingConfig.max_norm_residual`; y ≥ 0 by admissibility — assert before clip with 1e-9 slack). Eval heuristic per arm: `h_hat[s, i] = hl(i, s) + side_len * yhat[s, i]` where model outputs are already in [0, 4] (softplus+clamp convention below).

**Binding budgets (pre-registered).** K∈{2,4,8}: A 200/400/1600, B 100/200/800, C 200/400/1600 (probe calibration). K=0 cells (A, B): calibrate at collect time with `C11P.calibrate_binding_budget` over the legsum arm on the 25 TEST worlds, grid (100, 200, 400, 800, 1600, 3200); store in the run manifest.

**Matched recipe (arms 1–4; deviations are bugs).** smooth-L1 (β=1.0) on ŷ vs y, AdamW(lr=2e-4, weight_decay=1e-4), grad-clip 1.0, batch 1024, 40 epochs, shuffle seeded per training seed. 3 training seeds `{0, 1, 2}` per (arm, config, K); torch/numpy seeded `10007 * (seed + 1) + 101 * config_idx + K`. Output-clamp convention for ALL arms: `yhat = clamp(softplus(raw), 0, 4.0)` (mirrors `C.ContinuousHeuristicModel.forward`).

**Run manifest.** `runs/c11_local/manifest.json`: per trained arm-cell — checkpoint path, param count, arm/config/K/seed, K=0 calibrated budgets, wall time. Checkpoints under `runs/c11_local/ckpt/{arm}__{cfg}{K}__s{seed}.pt`.

    2. **Segment-loop non-termination (found via a `train_hrmv2` smoke test that legitimately hung)**: per-row ACT halting is asynchronous; once TRAINING perturbs the Q-head even slightly, a row can halt early via the Q-driven branch, which immediately resets its carry and restarts it on its OWN step-clock — permanently desynchronized from the rest of the batch. `carry.halted.all()` then requires every row's independent, exploration-randomized clock to land on a halt on the SAME absolute segment call — empirically verified to NOT happen within 3000 segments (27.8s) at this arm's real `batch_size=128` once training has run a few steps (clean at n≤16, breaks down by n=128). Fixed with a documented, generous safety cap (`_PER_BATCH_SEGMENT_CAP = 200`, ~50x `halt_max_steps`'s tiny-test value / ~25x the paper-faithful default) — preserves the one-optimizer-step-per-segment mechanism and real Q-learning dynamics; only changes when a batch's loop stops waiting for full synchronization.
    3. **Registry adapter signature mismatch (found via an end-to-end `run_train`→`run_eval` smoke test)**: registering `train=train_hrmv2` directly silently bound the core module's `epochs` argument to `train_hrmv2`'s `hrmv2_cfg` parameter (positional-slot collision — `train_hrmv2`'s signature has an extra `hrmv2_cfg` param the registry's 5-argument `train(cell, bundles, seed, cfg, epochs)` contract has no slot for). Fixed with a thin `_train` adapter inside `register_hrmv2_providers` that threads `hrmv2_cfg=hrmv2_config()` explicitly and matches the registry's exact signature. A regression test (`test_run_train_run_eval_end_to_end_through_registry`) now exercises the REAL `run_train`→`run_eval` dispatch chain, not `train_hrmv2` called directly — no unit test calling `train_hrmv2` with explicit kwargs (as every other test does) could have caught this class of bug.
